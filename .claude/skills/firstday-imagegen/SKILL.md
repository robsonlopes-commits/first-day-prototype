# First Day image generation

Script: `npm run image -- --prompt "..." --out <name> [--ref <png> ...] [--aspect 16:9] [--size 1K] [--model lite|pro] [--dry-run]`
Default model `gemini-nano-banana-2.1` (the docs recommend it for new projects, same 1K price as Lite). `--model lite` is the cheapest but is not built for reference images. Output goes to `public/assets/custom/<name>.jpg` (the API only returns JPEG), the prompt is logged in `public/assets/custom/PROMPTS.md`, and the page uses it with `customImg('<name>.jpg')` from `src/lib/assets.js`.

## Setup (once, done by the human)
Key in `.env.local` as `GEMINI_API_KEY=...` (gitignored; the repo is public). Never print, read back or commit the key. If the script says the key is missing, stop and tell the user.

## Cost discipline (paid API, org cost rules apply)
- Show the estimated cost per image (the script prints it). The owner pre-approved generating as many images as a task needs (a few cents each); keep a running count and report the total.
- Draft at 1K. Prefer 1K for everything (hero images at 16:9 1K are enough for the prototype); use 2K only when a large full-bleed hero looks soft.
- Re-use existing images when they fit: check `public/assets/shop`, `public/assets/custom`, and the production pages before generating.

## Purpose and what is allowed
The owner uses AI images to explore concepts visually BEFORE paying for real photo shoots. They are mockups: realistic enough to judge emotion, composition and fit. The owner explicitly approved all of the following, no further permission needed:
- Children and families in everyday moments, including children eating or holding gummies, vitamins and supplements.
- AI-generated product images (bottles, packaging, products in hands, on tables, in lunchboxes). For packaging accuracy, pass the real product cutouts from `public/assets/shop` (for example `kids-multi.png`, `kids-prob_4b7651d5-86e6-4eb3-8d96-e6d26e57c0e4.png`, `kids-brain.png`, `kids-mag.png`, and the `teens-`, `woman-`, `men-` equivalents) with `--ref` and ask the model to keep the label exactly. Perfect fidelity is not required for a mockup, but check that it looks like First Day.
- Text inside the image when it is needed (a note, a sign, a label, an infographic headline). Keep it short and spelled correctly; check the result carefully.
- Any scene that serves the story: kitchens, school, bedtime, sports, offices, outdoors.

## First Day packaging rules and the bottle photo recipe (learned from the owner, proven on `aio-buybox-kids.jpg`)

### What the real bottle looks like (use it in every prompt that shows bottles)
- **Cap and lid.** The upper cylinder is a white cap with a very faint cool blue-grey tint (the band behind the first day logo). Its TOP surface, when the camera is slightly above, is the SAME white. It is never green, red, teal, purple, beige, cream, brown or grey.
- **The lid is perfectly flat and smooth.** A flat, solid, matte disc: no rim, no lip, no recess, no hollow, no hole, no groove, no inner circle. The model tends to draw a shallow open tub with a raised rim and a recessed inside.
- **What is printed on the lid.** A small blue line-art First Day bird exactly in the center, a thin circular line of small blue uppercase text around the inner edge ("... TWIST TO FIGHT MODERN HEALTH CHALLENGES*" with a thin curved arrow), nothing else. In a front or slightly raised view it almost disappears but must be there, with the lid's perspective: a tiny squashed bird in the middle of the elliptical top and a very thin squashed ring of marks along the edge, barely legible, light blue, delicate. Never bold lettering, never big readable words, never color.
- The color lives only in the wavy label and the bottom tub. The real cutouts in `public/assets/shop` are shot from the front, so the model invents the top and usually tints it with the label color.
- Real references kept locally (gitignored, never commit them, they show a personal desk): `reference/bottle-photos/bottle-in-hand.webp` (shape of the lid, held bottle) and `reference/bottle-photos/lid-top-from-above.webp` (what is printed on the lid). If they are missing, ask the owner for a real photo of the bottle and of the lid from above.

### Recipe, in this order (each step is a strict minimal edit on top of the previous result)
Always keep the previous version next to the result (`<name>-v1.jpg` is the first generation) so the owner can compare, log every prompt in `PROMPTS.md`, and inspect with a crop and enlarge (`sips -c <h> <w> --cropOffset <y> <x> file --out crop.jpg`, then Read it) before moving on.
0. **Generate the scene** with the four real cutouts as `--ref` (`sips -Z 900` first) at 1K. For any prompt that shows the bottles from above add: "The lid top is the same bright white as the upper front band of the bottle, a perfectly flat smooth closed disc with no rim, no recess and no hole, not colored, not beige, not cream, not grey." Often this already fixes steps 1 and 2.
1. **White lid tops** (if the tops came out colored). `--ref` the scene. Prompt: "Edit this photo with a strict, minimal edit. Keep everything exactly the same (people, kitchen, composition, crop, lighting, the four bottles, every label, logo and text, exact positions and sizes). Change only ONE thing: the thin visible top surface of each bottle lid. Repaint all lid tops in the exact same bright white with a very faint cool blue-grey tint as the white upper front band, with only soft light shading, one continuous white cap, NOT beige, NOT cream, NOT brown, NOT grey and NOT colored. Do not change anything else." The "NOT beige" wording matters: the first attempt without it came out beige.
2. **Flat smooth lid.** `--ref` 1) the scene, 2) `bottle-in-hand.webp` (shape reference only). Prompt: same strict opening, then "Image 2 is a real photo of the real bottle, used ONLY as a shape reference for the lid: a perfectly flat, smooth, solid disc with no rim, no lip, no recess, no hollow, no hole, no groove, no inner circle, one continuous smooth matte surface in the same bright white. In image 1 each lid looks like a shallow open tub. Repaint all four as a flat smooth closed disc seen from slightly above as a clean smooth ellipse of white, with soft shading and a very thin rounded edge (ignore the colors and background of image 2). Do not change anything else."
3. **Lid artwork in perspective.** `--ref` 1) the scene, 2) `lid-top-from-above.webp` (reference for what is printed only). Prompt: strict opening, then "Change only the printed artwork on the lid top of each bottle. Image 2 shows the real lid from directly above (ignore its colors, hand and background): a small blue line-art bird exactly in the center, a thin circular line of small blue uppercase text around the inner edge and a thin curved arrow. In image 1 the lids are seen from slightly above, so keep the same strong perspective foreshortening as the lid ellipse: the bird is a tiny squashed blue line drawing in the center and the ring of text is a very thin, tiny, squashed elliptical line of blue marks following the edge, barely legible. Subtle, delicate, thin lines, light blue, no big letters, no readable words, nothing colorful. The surface stays smooth, flat and white. Do not change anything else."
4. **Label text restoration, always LAST.** Every edit re-renders the whole picture, so the small print degrades over versions. `--ref` 1) the scene, 2 to 5) the real high resolution front views of the bottles from left to right (`sips -Z 1400` first). Run it at `--size 4K` (about $0.11). At 1K or 2K a bottle is only 180 to 360 px wide and the small print stays mushy; at 4K the logo, big names and the bottom line come out crisp. Prompt: "Edit image 1 with a strict, minimal edit that restores the print quality of the packaging, at the highest possible resolution. Keep everything exactly the same (people, kitchen, composition, colors, tones, lighting, soft depth of field, the bottles, their positions, sizes, perspective and the flat white lids with their tiny bird and text ring). Change only the printed text and graphics on the four labels, which are soft and garbled. Images 2 to 5 are the real front views of the four bottles from left to right. Redraw every printed element to match its reference exactly with natural photographic sharpness: the logo, KIDS (or the audience word), the NO JUNK seal with its ring text, the product name, the small ingredient lines line by line, the certification badges and 60 GUMMIES | DIETARY SUPPLEMENT, following the curve and perspective of each bottle. Absolutely no glow, no halos, no colored outlines, no color fringing, no oversharpening, no change of saturation. Do not change anything else." The "no glow, no halos" sentence is mandatory: the 2K attempt without it produced colored halos around the bottles.
5. **One restoration pass only.** A second 4K pass that retyped the exact small lines made the text worse and brought the halos back. Keep the best single pass. A few letters in the tiny ingredient lines and the ring text inside the seal will stay wrong (for example "DRAIN" for BRAIN); they are mockup quality, say so in the summary. Only a real studio photo makes them exact.
5b. **Scenes where the bottle is small in the frame (people photos, 4:5).** Do all of steps 1 to 4 in ONE edit at `--size 2K` (about $0.05): ref 1) the scene, 2) the real front view of that exact bottle (`sips -Z 1400`), 3) `bottle-in-hand.webp`, 4) `lid-top-from-above.webp`. Ask for the lid white, flat and smooth, the lid artwork only if the lid top is visible, and the label redrawn from image 2, with the "no glow, no halos" sentence, and "strict pixel-aligned edit" so a before/after pair stays aligned. Also say: "the bottle is fully closed and opaque, with its lid on it, no transparent or glass parts, no open mouth, and no loose lid, cap or disc lying anywhere (remove any loose lid)": the model otherwise keeps open glass-jar bottles and stray lids from the first generation, and the real bottle is neither. Run it from the ORIGINAL image, never from a previous fix. Batch script used for the 16 All-in-1 day photos: one job per scene, 4 in parallel, then review every result at 1000 px.
5c. **The "sunken lid" problem in people scenes, and what the correct ones look like.** The recurring defect is a lid that looks sunken like a dish: a bright raised rim around a darker, greyer or bluer inner ellipse. The correct lid (studied on the images the owner approved: Kids bedtime, Teens morning, school and dinner) is: a flat top face lit uniformly, as bright as or brighter than the white band below it; NO darker, greyer or bluer inner area, NO inner ellipse, NO shadow inside, NO raised rim, only a hairline thin lighter rounded edge; on the face a small, clearly visible blue line-art bird in the center and a thin ring of tiny blue text running right next to the outer edge, printed flat and squashed by the perspective. Asking for a "very faint" artwork made it worse (the ring became an inset line, which reads as a recess), so ask for the artwork as printed, clearly but small. Best method: pass two close crops of approved lids as extra refs (`reference/bottle-photos/correct-lid-teens-school.jpg` and `correct-lid-kids-bedtime.jpg`) and say "copy exactly the lid top look of images 5 and 6", plus the description above. Also add "the bottle keeps exactly the same size, position and angle as in image 1, do not enlarge, shrink or move it" (one pass once blew a small bottle up three times, kids dinner). Always start from the ORIGINAL photo, crop each lid at full 2K resolution and compare it with the approved crops before accepting; the owner judges the lids at that zoom.
5d. **Lid still sunken after full-image edits: patch only the lid (this is what finally worked).** Editing the whole 4:5 photo kept giving a thick raised rim around a recessed face, three times in a row, because the model spends its pixels on the whole scene. The fix is a close-up lid edit composited back:
  1. Crop a small region around the lid and the top of the logo band from the full-size image (for example 540x320 px of a 1856 px wide photo): `sips -c <h> <w> --cropOffset <y> <x> in.jpg --out crop.jpg` (NOTE: `--cropOffset` takes y first, then x; in zsh pass the numbers literally, not through an unquoted variable).
  2. Edit the crop with `npm run image --aspect 16:9 --size 2K` and refs: 1) the crop, 2 to 4) `reference/bottle-photos/correct-lid-teens-school.jpg`, `correct-lid-kids-bedtime.jpg`, `correct-lid-zoom.jpg`. Prompt: "Edit image 1, a close-up crop of the top of a First Day bottle, with a strict minimal edit: keep the silhouette, width and height, label, logo, colors, lighting and background exactly the same. Change ONLY the lid top face and its edge. Images 2, 3 and 4 are crops of bottles whose lids are CORRECT: copy that lid top exactly. The lid is a thin flat cap: its flat face runs all the way to the outer edge and meets the side wall at one single crisp hairline-thin rounded edge. Remove any thick raised rim, border, lip and step, and make sure the face is not sunken: it is level with its edge. Evenly lit bright white face, no darker, greyer or bluer inner area, no shadow. Keep the small blue bird in the center and the thin ring of tiny blue text close to the outer edge, printed flat and squashed by the perspective. Do not change anything else." The model keeps the geometry of such a crop, so the result lines up.
  3. Composite the patch back with `tools/blend-patch.swift` (compile once: `swiftc -O tools/blend-patch.swift -o /tmp/blend`): `blend base.jpg patch.jpg out.jpg <x> <y> <w> <h> <fullTop> <fadeEnd> <featherX>`, where x, y, w, h are the crop rectangle in the base image, rows 0..fullTop of the patch are fully replaced, the mask fades to nothing at fadeEnd (stop above the logo, so the label from the full-image pass is untouched), and featherX is the side feather in px. View the result at 2x before accepting; edges should be invisible.
  This was applied to the Kids morning, school and dinner photos after the owner marked them wrong while Kids bedtime and Teens morning, school, dinner were right.
5e. **Bottle size in people scenes (measured on the approved photos).** In the 4:5 day photos the bottle is small: about 12 to 15 percent of the image width and 18 to 22 percent of the image height (kids school 13 x 20, kids bedtime 12 x 18, teens morning and school 14 x 21), roughly as tall as a drinking glass and about half the height of a face; if it is smaller than that it is a prop far away (kids dinner is 8 x 12, fine only when it sits far back). A bottle that fills a fifth of the width and almost a third of the height (kids morning first had 21 x 30) looks absurd. Say the target in the prompt, in percent AND relative to an object in the frame ("its top is at the same height as the top of the drinking glass, about 19 percent of the image height and 12 percent of the width, clearly narrower than the bowl, it must NOT be taller than the glass").
  **Models will not shrink an object that is already in the photo** (three attempts with "scale it down to two thirds" returned the same size). Do it in two edits: 1) remove the bottle ("completely remove the bottle and fill the space with the natural table, bowl, napkin and sweater, no bottle anywhere"), 2) add a new one with the size and position in percent of the image (base at about 85 percent of the height, center at about 59 percent of the width, a little further back than the glass), the real front view of that bottle as ref 2 and two approved lid crops as refs 3 and 4, plus the soft contact shadow. Generate 3 variants and pick the one closest to the numbers. Then fix the lid with the patch method (5d), which was needed again here. Order: size first, lid patch last.
6. **Save for the repo downscaled.** A 4K JPEG is about 7.5 MB. Use `sips -Z 2048 -s formatOptions 88 in.jpg --out public/assets/custom/<name>.jpg` (about 0.7 MB, sharp on retina) and keep the 4K original outside the repo (scratchpad).
Total cost of the full recipe on one scene: about $0.25 (1K steps about $0.034 each, the 4K restoration about $0.11). Keep the scene composition identical across steps so the page never changes visually.

For brand and claim context before generating an infographic or any image with words, read `firstday-brand-knowledge` (approved claims only).

## Guardrails that still apply
- Dignified, everyday, fully clothed, diverse people; no real person's likeness or celebrity; nothing sexual, violent, frightening or humiliating; no distress beyond mild everyday frustration.
- Do not generate regulated health claim imagery (before/after body or health transformations, medical or disease claims, doctors vouching, fake certifications or awards). If a concept needs one, flag it to the owner instead. Exception the owner asked for: the All-in-1 "without / with First Day" slider compares everyday moods in the same scene (a tense breakfast versus a happy one). Keep any such pair about mood and routine, never about bodies, symptoms or measurable results.
- Negative "before" twin of an existing photo: pass the happy photo as `--ref` and ask for a strict pixel-aligned edit (same crop, zoom, people and objects; remove the bottle and gummies; change only expressions and body language). It keeps the pair aligned for a slider.
- Every AI image is a MOCKUP: say so in the final summary, keep the prompt in `PROMPTS.md`, and never present it as real photography. Replacing it with real photography is the expected next step.
- If the API refuses a prompt, rephrase to a safer everyday scene. Never try to bypass a refusal.
- Inspect every result with the Read tool: reject warped faces or hands, uncanny teeth, wrong or garbled text, and anything off-brand.

## Prompt recipe
Start from this base and add the scene: "Clean bright editorial photo, soft natural window light, airy white and light blue palette with accents of noon blue (#476DED), shallow depth of field, uncluttered. Add 'plenty of empty space for text' for backgrounds, and state explicitly when you do want people, products or text in the image." State the use ("hero background, 16:9, empty left third") and the aspect ratio with `--aspect` (1:1, 4:5, 16:9, 9:16).
When using references: "Use the attached product exactly as is. Do not change its label, shape or colors. Place it in ..." (the model may still alter details, so inspect the result and retry if the label drifts too far).

## After generating
1. Open the image and check it: no garbled text, no extra labels, no faces, on brand (bright, clean, white/blue). Reject and retry with a fixed prompt if not.
2. Wire it with `customImg(...)` following the `firstday-design` skill (white page, sofia-pro, no shadows).
3. Keep files reasonable: prefer 1K, and if a JPG is larger than about 1.5 MB, tell the human (repo size, page speed).
4. Note the generated asset in the summary so the human knows it is AI-generated.
